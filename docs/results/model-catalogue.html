Open-Weight Model Catalogue

Every open-weight family that could serve as a teacher/student pair for the owl/cat and backdoor experiments. For each model: sizes; whether base, instruct and quantized versions exist; architecture; licence; whether it fits one 48 GB L40S; whether its chat template inserts a default system prompt; and how open its training data is. A research agent compiled it from Hugging Face model pages, raw chat templates and the vLLM 0.32 registry. I re-checked the ten shortlisted repos against the Hugging Face API: all exist, with the licences and gating shown. Many entries are newer than my own training data, and cells marked (?) could not be verified.

Shortlist for this project

Ranked by fit on one L40S, a public base and instruct pair, not Qwen, open data, a different architecture, and how the chat template behaves.

  1. OLMo 3 7B (allenai/Olmo-3-1025-7B + Olmo-3-7B-Instruct). Pretraining and mid-training data are fully open, and there are about 1,500 intermediate checkpoints across pretrain / mid-train / long-context. You could test the "Qwen mid-training" hypothesis directly by comparing checkpoints before and after mid-training.
  2. Template: it inserts a fixed "function-calling assistant" system prompt, so always pass an explicit system message.
  3. If you want a template that adds nothing, OLMo 2 7B/13B is a drop-in alternative (4K context).
  4. Llama 3.1 8B (base + Instruct). The standard non-Qwen dense baseline, with first-class peft and vLLM support.
  5. Template: it always prepends a fixed "Cutting Knowledge Date: December 2023 / Today Date: 26 Jul 2024" block, which is deterministic and harmless if both teacher and student use it.
  6. Access: gated (manual approval); data closed. Avoid Llama 3.2 because its date changes daily.
  7. NVIDIA Nemotron-Nano-9B-v2 (Base + instruct). A Mamba-2 hybrid, so a different architecture, with largely open pretraining data (Nemotron-CC v2, 20T tokens) and native vLLM support.
  8. Template: it emits an empty system turn and thinks by default; use /no_think.
  9. License: the NVIDIA Open Model License.
  10. Gemma 4 12B (or E4B for cheaper runs). Base + instruct, Apache-2.0, ungated, and the first Gemma with a real system role.
  11. Template: it adds nothing. The 12B always appends an empty thought block to the generation prompt; the E4B does not.
  12. Setup: it needs transformers v5, and LoRA targets must be restricted to the language model. Data closed.
  13. IBM Granite 4.1 8B (base + instruct). Plain dense, Apache-2.0, ungated, native vLLM support.
  14. Template: it adds nothing (verified). A clean "different-vendor dense" control.
  15. Avoid Granite 4.2 for this: no new base, thinking on by default, and a ChatML template that does not match the 4.1 base.
  16. Olmo Hybrid 7B. A Gated DeltaNet 3:1 hybrid like Qwen3.5, but trained on OLMo's open data. It separates "Qwen3.5 architecture" from "Qwen training data" as explanations.
  17. Caveats: post-training is preliminary (SFT/DPO only), it needs transformers ≥5.3, and it uses the same function-calling default prompt as OLMo 3.
  18. Mistral Nemo 12B (Base-2407 + Instruct-2407). Apache-2.0, ungated, dense, with a different tokenizer (Tekken).
  19. Template: it has no system role, so the system text is merged into the user turn. vLLM defaults to mistral_common for mistralai repos, so check token-level parity with the HF render.
  20. Prefer it over Ministral 3, whose HF template injects a ~2.3 KB Le Chat prompt that vLLM's mistral_common does not.
  21. SmolLM3-3B (Base + instruct). Fully open data and mid-training/SFT checkpoints, and very cheap to run.
  22. Template: it date-stamps every prompt and thinks by default. Its system turn is also left unclosed unless tools are passed (verified template bug). Use /system_override and enable_thinking=False.

Runners-up: Falcon-H1-7B (parallel attention+Mamba2 hybrid, template adds nothing, but closed data and the TII license) and Granite 4.0 H-Tiny (Mamba2/MoE hybrid, but a fixed safety system sentence).

Avoid: - R1-Distill-Llama-8B: no distinct base and a forced <think>. - Phi: no base checkpoints. - gpt-oss-20b: no base, an identity prompt that cannot be removed, and a tight fit.

How this was checked, legend, and findings that matter here

How this was checked. I ran four parallel research agents and covered Qwen myself. - Sources: model metadata (size, creation date, license, gating) comes from the Hugging Face API. Chat templates come from each repo's raw tokenizer_config.json or chat_template.jinja on main. - Template column: every "Default system prompt" cell comes from rendering the template with jinja2 on a single user turn (add_generation_prompt=True), not from model cards. - vLLM: checked against the vLLM v0.32.0 model registry (tag dated 2026-10-18). - transformers: checked against the transformers source on main (~v5.22). - Gated repos: templates were read from ungated mirrors (unsloth, mlx-community), as noted in the cells. - Re-verified by me: I re-rendered the templates of every shortlist model. I also confirmed that about 30 of the more surprising post-cutoff repos exist via the HF API (e.g. Muse Glimmer, Gemma 4, Qwen3.8, DeepSeek V4, Granite 4.2).

Legend - Release is the month of public release. Where only the repo creation date is known, that date is used. - Fit on 1×L40S: - "yes" means bf16 weights plus LoRA fit on one 48 GB card. Weights take about 2 bytes per parameter, and for MoE models the total parameter count is what matters. - "QLoRA/multi" means the model needs QLoRA or several GPUs. - "no" means a very large MoE. - "Adds nothing" means the template renders no system turn when the conversation has no system message. - "(?)" marks a cell I could not verify.

Cross-cutting findings that matter for this project - Teacher and student templates must match token for token. Many templates stamp today's date into the prompt, so the same prompt renders differently from day to day. These are Llama 3.2, SmolLM3, Apertus 2509, Granite 3.1–3.3, Mistral Small 3/3.1 and gpt-oss. - Thinking is on by default in many 2025–26 releases: Nemotron Nano v2 / 3 / 3.5, Qwen3.5+, Granite 4.2, Gemma 4 when enabled, GLM-4.7-Flash and LFM2.5/3. Teacher number sequences will come with <think> traces unless you turn thinking off (enable_thinking=False, /no_think, or the model's equivalent). - Mistral hazard: vLLM and HF render prompts differently. vLLM v0.32 tokenizer_mode=auto switches every mistralai repo to mistral_common, which inserts no default system prompt. HF AutoTokenizer with the repo's jinja template inserts a long "Le Chat" prompt for Ministral 3, Small 3/3.1/4 and Large 3. Your vLLM teacher and HF student would then see different prompts. - Qwen in disguise: several non-Qwen-branded models are Qwen underneath. These are DeepSeek-R1-Distill-Qwen-*, R1-0528-Qwen3-8B, Step3-VL-10B (Qwen3-8B decoder) and MiMo-V2.6-Distill-Qwen-9B. MiMo-7B was pretrained from scratch but uses the Qwen2 tokenizer and a Qwen-style template.
